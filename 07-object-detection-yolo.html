Why does this matter?چرا این مهم است؟
A mobile robot in a warehouse can't just know "this is a picture of a warehouse" — it needs to know exactly where a person is standing, where a forklift is moving, so it can choose a safe path. Object Detection is what gives the robot "location," not just a "label." یک ربات متحرک در انبار فقط دانستن «این یک عکس از انبار است» به کارش نمی‌آید — باید دقیقاً بداند کجا آدم ایستاده، کجا فورک‌لیفت در حال حرکت است، تا مسیرش را امن انتخاب کند. Object Detection همان چیزی است که به ربات «مکان» می‌دهد، نه فقط «برچسب».

1. Classification vs. Detection۱. تفاوت Classification با Detection

Classification only says "this image is a dog" — one label for the whole picture. Detection1 goes further: it says "there's a dog here, boxed like this, and a cat over in that corner too." That is, it gives both location (Where) and type (What) for every object separately, for several objects at once in the same picture. Classification فقط می‌گوید «این تصویر یک سگ است» — یک برچسب برای کل عکس. اما Detection۱ فراتر می‌رود: می‌گوید «یک سگ اینجاست، با این باکس دور آن، و یک گربه هم آن گوشه است». یعنی هم مکان (Where) و هم نوع (What) هر شیء را جدا جدا می‌دهد، آن هم برای چند شیء همزمان در یک عکس.

For a mobile robot in a warehouse, this distinction is critical: simply knowing "there's a person in this photo" isn't enough — the robot needs to know exactly where in the scene that person is, so it can adjust its path. برای یک ربات متحرک در انبار، این تفاوت حیاتی است: صرفاً دانستن «در این عکس آدم هست» کافی نیست؛ ربات باید بداند آن آدم دقیقاً کجای صحنه است تا بتواند مسیرش را تغییر دهد.

2. Bounding Box۲. Bounding Box

Bounding Box2 means a rectangle drawn around an object to mark its location. It's usually described with 4 numbers: Bounding Box۲ یعنی مستطیلی که دور یک شیء کشیده می‌شود تا مکانش را مشخص کند. معمولاً با ۴ عدد توصیف می‌شود:

  • x_min, y_min, x_max, y_max — the top-left and bottom-right corners of the rectangleگوشه بالا-چپ و پایین-راست مستطیل
  • orیا center_x, center_y, width, height — the box center plus width and height (the format YOLO itself uses)مرکز باکس به‌همراه عرض و ارتفاع (فرمتی که خود YOLO از آن استفاده می‌کند)

3. IoU (Intersection over Union)۳. IoU (Intersection over Union)

IoU3 is a metric for measuring how much two boxes overlap — for example, the box a model predicted versus the true box (Ground Truth) a human labeled. IoU۳ معیاری است برای اندازه‌گیری میزان هم‌پوشانی دو باکس — مثلاً باکسی که مدل پیش‌بینی کرده در برابر باکس واقعی (Ground Truth) که انسان لیبل زده.

$$ IoU = \frac{\text{Intersection Area}}{\text{Union Area}} $$
Numeric example: two boxes overlap in a region of 50 square units, and their union (the total area covered by either box) is 100 square units. So IoU = 50 / 100 = 0.5. Common convention: if IoU ≥ 0.5, the prediction is counted as a "correct detection." مثال عددی: دو باکس داریم که ناحیهٔ اشتراکشان ۵۰ واحد مربع و ناحیهٔ اجتماعشان (کل فضایی که هر دو باکس روی هم می‌پوشانند) ۱۰۰ واحد مربع است. پس IoU = 50 / 100 = 0.5. قرارداد رایج: اگر IoU ≥ 0.5 باشد، آن پیش‌بینی «تشخیص درست» حساب می‌شود.

4. NMS (Non-Maximum Suppression)۴. NMS (Non-Maximum Suppression)

A detection model usually proposes several overlapping boxes for a single object (because at various points around the object it "thinks" it has spotted something). NMS4 cleans up these duplicate boxes: the highest-scoring box is kept, and other boxes that have high IoU with it (i.e. probably showing the same object again) are removed. مدل تشخیص معمولاً برای یک شیء واحد، چندین باکس روی‌هم‌افتاده پیشنهاد می‌دهد (چون در نقاط مختلف اطراف شیء «فکر می‌کند» چیزی دیده). NMS۴ این باکس‌های تکراری را جمع می‌کند: پرامتیازترین باکس نگه داشته می‌شود و باکس‌های دیگری که IoU بالایی با آن دارند (یعنی احتمالاً همان شیء را دوباره نشان می‌دهند) حذف می‌شوند.

5. Precision / Recall and 6. mAP۵. Precision / Recall و ۶. mAP

$$ Precision = \frac{TP}{TP+FP}, \quad Recall = \frac{TP}{TP+FN} $$
Workshop example: a warehouse photo has 10 real people in it. The model correctly detected 8 (TP=8), missed 2 (FN=2), and 3 times mistakenly called something a "person" that wasn't one (FP=3).
Precision = 8 / (8+3) = 8/11 ≈ 0.73
Recall = 8 / (8+2) = 8/10 = 0.8 مثال کارگاهی: در یک عکس انبار ۱۰ نفر واقعی حضور دارند. مدل ۸ نفر را درست تشخیص داد (TP=8)، ۲ نفر را جا انداخت (FN=2)، و ۳ بار هم اشتباهاً چیزی را «نفر» نامید که نفر نبود (FP=3).
Precision = 8 / (8+3) = 8/11 ≈ 0.73
Recall = 8 / (8+2) = 8/10 = 0.8

This means 73% of the things the model called "person" really were people (Precision), and out of the 10 real people, it found 80% of them (Recall). These two metrics usually trade off against each other. یعنی مدل ۷۳٪ از چیزهایی که «نفر» نامید واقعاً نفر بودند (Precision)، و از کل ۱۰ نفر واقعی، ۸۰٪شان را پیدا کرد (Recall). این دو معیار معمولاً با هم بده‌بستان دارند.

mAP5 (mean Average Precision), in short, is the average Precision across several IoU thresholds and over all classes — the standard metric used to compare different object detection models. mAP۵ (mean Average Precision) به‌طور خلاصه میانگین Precision در چند آستانه مختلف IoU و روی همه کلاس‌هاست — معیار استانداردی که برای مقایسه مدل‌های مختلف تشخیص اشیا استفاده می‌شود.

7 & 8. What is YOLO۷ و ۸. YOLO چیست

YOLO stands for You Only Look Once6. Unlike older methods that scanned an image in several separate stages (first candidate regions, then examining each one), YOLO predicts all the boxes and classes in an image simultaneously in a single pass through the neural network. That's why it's so fast, and why it's such a good fit for real-time applications like robotics. YOLO مخفف You Only Look Once۶ است. برخلاف روش‌های قدیمی‌تر که تصویر را در چند مرحله جداگانه اسکن می‌کردند (اول نواحی احتمالی، بعد بررسی هرکدام)، YOLO در یک عبور واحد (Single Pass) از شبکه عصبی، همزمان همهٔ باکس‌ها و کلاس‌های موجود در تصویر را پیش‌بینی می‌کند. به همین دلیل بسیار سریع است و برای کاربردهای Real-time مثل رباتیک بسیار مناسب. 

from ultralytics import YOLO
model = YOLO("yolo11n.pt")
results = model("warehouse.jpg")

Datasets and Labelsدیتاست و Label

A Dataset isn't just a collection of images; it also needs Labels (or Annotations7) — meaning for every object in every image, its class and exact box location must be specified. For instance, in a warehouse dataset we'd have classes like person, forklift, and pallet. یک Dataset فقط مجموعه‌ای از عکس نیست؛ باید Label (یا Annotation۷) هم داشته باشد — یعنی برای هر شیء در هر عکس، کلاس آن و مکان دقیق باکسش مشخص شده باشد. مثلاً در یک دیتاست انبار، کلاس‌هایی مثل person، forklift و pallet خواهیم داشت.

The YOLO label format looks like this:فرمت Label در YOLO این شکلی است:

class_id center_x center_y width height

where the coordinates are Normalized8 — meaning between 0 and 1, relative to the full image's width and height (for example center_x=0.5 means exactly the middle of the image width). A concrete example of one label line: که مختصات Normalize۸ شده‌اند — یعنی بین ۰ و ۱، نسبت به عرض و ارتفاع کل تصویر (مثلاً center_x=0.5 یعنی دقیقاً وسط عرض تصویر). مثال دقیق یک خط Label: 

0 0.52 0.44 0.18 0.60

That means: class number 0, box center at 52% of the image width and 44% of the height, with 18% width and 60% height.یعنی: کلاس شماره ۰، مرکز باکس در ۵۲٪ عرض و ۴۴٪ ارتفاع تصویر، با عرض ۱۸٪ و ارتفاع ۶۰٪ تصویر.

The standard folder structure of a YOLO dataset:ساختار پوشهٔ استاندارد یک دیتاست YOLO:

dataset/
├── images/
│   ├── train/
│   └── val/
├── labels/
│   ├── train/
│   └── val/
└── data.yaml

And the data.yaml file, which tells the model where the dataset lives and what the classes are:و فایل data.yaml که به مدل می‌گوید دیتاست کجاست و کلاس‌ها چه هستند:

path: ./dataset
train: images/train
val: images/val

names:
  0: person
  1: forklift
  2: pallet

Code to train a model on this dataset:کد آموزش (Train) مدل با این دیتاست:

from ultralytics import YOLO
model = YOLO("yolo26n.pt")
model.train(data="data.yaml", epochs=50, imgsz=640)

Ready-Made Datasetsدیتاست‌های آماده

Good news: you don't always need to build a dataset from scratch. Several large, public datasets already exist:خبر خوب: همیشه لازم نیست دیتاست را از صفر بسازی. چند دیتاست بزرگ و عمومی وجود دارند:

  • COCO9: 80 common classes (person, car, truck, bicycle, dog, cat, chair, bottle, etc.), with its Detection version containing over 123,000 images (train+val) and around 886,000 bounding boxes. COCO۹: ۸۰ کلاس رایج (person, car, truck, bicycle, dog, cat, chair, bottle و...)، نسخهٔ Detection آن بیش از ۱۲۳ هزار تصویر (train+val) و حدود ۸۸۶ هزار Bounding Box دارد.
  • Pretrained10 YOLO models are already trained on COCO, so you can run model("image.jpg") right away, with no extra training at all. مدل‌های Pretrained۱۰ YOLO از قبل روی COCO آموزش دیده‌اند، پس همان اول می‌توانی model("image.jpg") را اجرا کنی، بدون هیچ آموزش اضافه‌ای.
  • Objects365: 365 classes, over 1.7 million training images.Objects365: ۳۶۵ کلاس، بیش از ۱.۷ میلیون تصویر آموزشی.
  • Open Images V7: 601 classes, over 1.7 million training images.Open Images V7: ۶۰۱ کلاس، بیش از ۱.۷ میلیون تصویر آموزشی.
  • Ultralytics also supports other datasets such as LVIS and Argoverse.Ultralytics از دیتاست‌های دیگری مثل LVIS و Argoverse هم پشتیبانی می‌کند.
🏆 Golden rule:قانون طلایی: before spending time building a dataset, first check whether a suitable ready-made dataset already exists for your problem.قبل از اینکه وقت بگذاری و دیتاست بسازی، اول ببین یک دیتاست آمادهٔ مناسب برای مسئله‌ات وجود دارد یا نه.

When to Build a Custom Dataset?کِی دیتاست اختصاصی بسازیم؟

  • Always try a pretrained model first; if it works, you're done.اول همیشه مدل Pretrained را امتحان کن؛ اگر جواب داد، کارت تمام است.
  • When you have specific, custom classes — like "Digikala plastic pallet," a custom rack, a particular AGV model, damaged packaging, or a warehouse sign — the general-purpose model simply doesn't know these classes; this is where a custom dataset is necessary. وقتی کلاس‌های خاص و سفارشی داری — مثلاً «پالت پلاستیکی دیجی‌کالا»، قفسهٔ سفارشی، یک مدل خاص AGV، بسته‌بندی آسیب‌دیده یا تابلوی انبار — مدل عمومی اصلاً این کلاس‌ها را نمی‌شناسد؛ اینجا دیتاست اختصاصی لازم است.
  • Even for a common class like person, if your environment's conditions are unusual (a ceiling camera at a strange angle, a very dark warehouse, uncommon PPE clothing, heavy occlusion, or people far from the camera), a custom dataset from your own environment is still very valuable. حتی برای یک کلاس عمومی مثل person، اگر شرایط محیطت خاص باشد (دوربین سقفی با زاویه عجیب، انبار خیلی تاریک، لباس‌های PPE غیرمعمول، اکلوژن شدید، یا افراد خیلی دور از دوربین)، باز هم دیتاست اختصاصی از محیط خودت ارزش زیادی دارد.

Hybrid / Transfer Learning (a Bridge to Chapter 8)Hybrid / Transfer Learning (پل به فصل ۸)

The best approach usually isn't training from scratch, but rather: Pretrained Model + your dataset → Fine-tuning11 → Custom Model. A YOLO model has already learned concepts like edges, shapes, textures, people, and vehicles; you're just specializing that knowledge for your own warehouse. This is exactly the Transfer Learning12 we'll dig into further in Chapter 8. بهترین روش معمولاً Train از صفر نیست، بلکه: Pretrained Model + دیتاست خودت → Fine-tuning۱۱ → Custom Model. مدل YOLO از قبل مفاهیمی مثل لبه‌ها، شکل‌ها، بافت‌ها، آدم‌ها و وسایل نقلیه را یاد گرفته؛ تو فقط آن دانش را برای انبار خودت تخصصی می‌کنی. این همان Transfer Learning۱۲ است که در فصل ۸ عمیق‌تر بررسی می‌کنیم.

Collecting a Real Datasetجمع‌آوری دیتاست واقعی

Instead of downloading random images from the internet, the best approach is to record video from the robot's own camera in the real environment: AMR Camera → Warehouse Video → Extract Frames. به‌جای دانلود تصادفی عکس از اینترنت، بهترین کار این است که از دوربین خود ربات در محیط واقعی فیلم بگیری: AMR Camera → Warehouse Video → Extract Frames.

The variety this data should have: morning/night, bright/dark, quiet/crowded, near/far, people standing/walking/running, partial occlusion, different clothing, different aisles. This data is far more valuable than thousands of unrelated internet photos, because it captures exactly the real distribution of the robot's operating (deployment) environment. تنوعی که باید در این داده باشد: صبح/شب، روشن/تاریک، خلوت/شلوغ، نزدیک/دور، افراد ایستاده/راه‌رونده/دونده، اکلوژن جزئی (نیمه پنهان)، لباس‌های متفاوت، راهروهای متفاوت. این داده به‌مراتب ارزشمندتر از هزاران عکس نامرتبط اینترنتی است، چون دقیقاً توزیع واقعی محیط عملیاتی (Deployment) ربات را ثبت می‌کند.

⚠️ Common and Dangerous Mistake: Data Leakageاشتباه رایج و خطرناک: Data Leakage13

Suppose you have a 10-minute video at 30 frames per second: that's 18,000 frames. If you randomly split these frames between Train and Validation, frame number 100 and frame number 101 are nearly the same image (only 33 milliseconds apart!). The result: the model sees in Validation something it has already seen almost exactly in Train; the mAP number might show 98%, but this is completely misleading — the model's real performance on genuinely new data can be far lower. فرض کن یک ویدیوی ۱۰ دقیقه‌ای با ۳۰ فریم بر ثانیه داری: یعنی ۱۸,۰۰۰ فریم. اگر این فریم‌ها را به‌صورت تصادفی بین Train و Validation تقسیم کنی، فریم شمارهٔ ۱۰۰ و فریم شمارهٔ ۱۰۱ تقریباً همان تصویرند (فقط ۳۳ میلی‌ثانیه فاصله زمانی!). نتیجه: مدل در Validation چیزی می‌بیند که تقریباً عیناً در Train هم دیده بود؛ عدد mAP ممکن است ۹۸٪ نشان دهد، اما این کاملاً گمراه‌کننده است — عملکرد واقعی مدل روی داده‌ی واقعاً جدید می‌تواند خیلی پایین‌تر باشد.

The correct fix:راه‌حل درست: split by session or by day, not by random frame. For example, Monday and Tuesday's videos for Train, Wednesday for Validation, and Friday for Test. تقسیم بر اساس Session یا روز، نه بر اساس فریم تصادفی. مثلاً ویدیوهای دوشنبه و سه‌شنبه برای Train، چهارشنبه برای Validation، و جمعه برای Test.

History and Versions of YOLOتاریخچه و نسخه‌های YOLO

YOLO isn't a single model, but a family of architectures that has evolved over time: YOLOv1 → v2 → v3 → ... → v5 → v8 → v9/v10 → YOLO11 → YOLO26. Important note: not all of these versions were built by one single team — the YOLO ecosystem has several different research and implementation branches. Today the Ultralytics library supports versions v3, v5, v6, v8, v9, v10, YOLO11, YOLO12, and YOLO26. YOLO یک مدل واحد نیست، بلکه خانواده‌ای از معماری‌هاست که در طول زمان تکامل پیدا کرده: YOLOv1 → v2 → v3 → ... → v5 → v8 → v9/v10 → YOLO11 → YOLO26. نکتهٔ مهم: همهٔ این نسخه‌ها را یک تیم واحد نساخته — اکوسیستم YOLO شاخه‌های پژوهشی و پیاده‌سازی مختلفی دارد. امروز کتابخانهٔ Ultralytics از نسخه‌های v3، v5، v6، v8، v9، v10، YOLO11، YOLO12 و YOLO26 پشتیبانی می‌کند.

Recommendation for learning: YOLO11 is a mature, production-ready base and great for learning the concepts; YOLO26 (introduced January 2026) is the newest generation, with an end-to-end design optimized for edge deployment, and is recommended for new projects. In terms of code and API, the difference is minimal: توصیه برای یادگیری: YOLO11 پایه‌ای بالغ و مناسب Production است و برای یادگیری مفاهیم عالی است؛ YOLO26 (معرفی‌شده ژانویهٔ ۲۰۲۶) جدیدترین نسل است، با طراحی end-to-end و بهینه برای Edge Deployment، و برای پروژه‌های جدید توصیه می‌شود. از نظر کد و API تفاوت خیلی کم است: 

YOLO("yolo11n.pt")   # mature generation, production-ready
YOLO("yolo26n.pt")   # newest generation, optimized for edge

Official resources for further reading: docs.ultralytics.com/models and docs.ultralytics.com/datasets/detect. منابع رسمی برای مطالعهٔ بیشتر: docs.ultralytics.com/models و docs.ultralytics.com/datasets/detect.

What n / s / m / l / x Meann / s / m / l / x یعنی چه

Each family of models (e.g. yolo26) is released in several sizes: n (Nano), s (Small), m (Medium), l (Large), x (Extra Large). Suppose the ground-truth box and the predicted box have an intersection area of 30 square units, and their union area is 120 square units. What's the IoU? IoU = 30 / 120 = 0.25

A Real Detection: Finding a Red Ballیک تشخیص واقعی: پیدا کردن یک توپ قرمز

Two ways to find the same object in the same photo — classical color segmentation (Chapter 3's thresholding, but in HSV color space) versus a pretrained YOLO model. Both are legitimate engineering choices; which one you pick depends on your latency budget, your hardware, and how much the target's appearance varies. دو روش برای پیدا کردن همان شیء در همان عکس — segmentation کلاسیک بر پایه رنگ (همان thresholding فصل ۳، ولی در فضای رنگی HSV) در برابر یک مدل YOLO از‌پیش‌آموزش‌دیده. هر دو انتخاب مهندسی معتبری هستند؛ اینکه کدام را انتخاب کنی به بودجه Latency، سخت‌افزار، و میزان تغییرپذیری ظاهر هدف بستگی دارد.

Color segmentation is nearly free computationally and needs zero training data — but it only works because a red ball is reliably red. A YOLO model costs more compute but generalizes to objects that don't have one distinctive color, which is exactly the trade-off this whole chapter has been building toward. Segmentation رنگی تقریباً بدون هزینه محاسباتی است و به هیچ داده آموزشی نیاز ندارد — اما فقط به این خاطر کار می‌کند که یک توپ قرمز همیشه قرمز است. یک مدل YOLO هزینه محاسباتی بیشتری دارد ولی به اشیایی که یک رنگ متمایز ندارند هم تعمیم پیدا می‌کند — دقیقاً همان trade-off ای که کل این فصل داشت به آن می‌رسید.

Glossaryواژه‌نامه

1. Bounding Box / Detection
A detection method that specifies both the class and the location (box) for each object.روش تشخیص اشیا که برای هر شیء هم کلاس و هم مکان (باکس) را مشخص می‌کند.
2. Bounding Box
A rectangle around an object marking its location in the image.مستطیل دور یک شیء برای مشخص کردن مکانش در تصویر.
3. IoU (Intersection over Union)
The ratio of the intersection area to the union area of two boxes; a measure of overlap.نسبت مساحت اشتراک به مساحت اجتماع دو باکس؛ معیار سنجش هم‌پوشانی.
4. NMS (Non-Maximum Suppression)
An algorithm that removes duplicate boxes on the same object and keeps only the best one.الگوریتمی که باکس‌های تکراری روی یک شیء را حذف و فقط بهترین را نگه می‌دارد.
5. mAP
Average Precision across several IoU thresholds and all classes; the standard metric for comparing models.میانگین Precision در چند آستانهٔ IoU و روی همهٔ کلاس‌ها؛ معیار استاندارد مقایسه مدل‌ها.
6. YOLO
You Only Look Once — a family of object-detection models with fast, single-pass prediction.You Only Look Once — خانواده مدل‌های تشخیص اشیا با پیش‌بینی یک‌مرحله‌ای و سریع.
7. Annotation / Labeling
The process of manually marking the class and location of objects in images to build a dataset.فرایند مشخص کردن دستی کلاس و مکان اشیا در عکس‌ها برای ساخت دیتاست.
8. Normalize (coordinates)
Converting pixel coordinates into the 0–1 range relative to the image dimensions.تبدیل مختصات پیکسلی به بازهٔ ۰ تا ۱ نسبت به ابعاد تصویر.
data.yaml
A configuration file that tells a YOLO model where the dataset is and what the class names are.فایل تنظیمات که مسیر دیتاست و اسم کلاس‌ها را به مدل YOLO معرفی می‌کند.
9. Pretrained Model
A model already trained on a large dataset (like COCO).مدلی که از قبل روی یک دیتاست بزرگ (مثل COCO) آموزش دیده است.
11. Fine-tuning
Continuing to train a pretrained model on your own smaller, specialized dataset.ادامهٔ آموزش یک مدل Pretrained روی دیتاست کوچک‌تر و تخصصی خودت.
12. Transfer Learning
Using the knowledge a model learned on one problem for a similar new problem.استفاده از دانش یادگرفته‌شدهٔ یک مدل در یک مسئله، برای مسئله‌ای مشابه دیگر.
13. Data Leakage
When very similar or related data leaks between Train and Validation, making evaluation results misleading.وقتی داده‌های خیلی شبیه یا مرتبط بین Train و Validation درز می‌کنند و نتیجهٔ ارزیابی را گمراه‌کننده می‌کنند.
Train/Val/Test Split
Splitting a dataset into three separate parts for training, validation, and final testing.تقسیم دیتاست به سه بخش جدا برای آموزش، اعتبارسنجی و تست نهایی مدل.
14. Edge Device
A small, low-power computing device (like an onboard robot computer) that runs the model.دستگاه محاسباتی کوچک و کم‌مصرف (مثل کامپیوتر روی‌برد یک ربات) که مدل روی آن اجرا می‌شود.
15. OBB (Oriented Bounding Box)
A box that has a rotation angle in addition to location — for rotated objects such as a car seen from above.باکسی که علاوه بر مکان، زاویهٔ چرخش هم دارد — برای اشیای چرخیده مثل خودرو از بالا.
COCO
A large, well-known public dataset with 80 common classes, the most widely used object-detection benchmark.یک دیتاست بزرگ و معروف عمومی با ۸۰ کلاس رایج، پرکاربردترین بنچمارک تشخیص اشیا.
